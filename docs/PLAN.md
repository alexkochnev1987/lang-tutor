## 0. Что это

Система ежедневной подготовки (15 мин/день × 182 дня) к государственному
сертификационному экзамену по польскому языку на уровень **B1, grupa dla osób
dorosłych** — с персональным словарём, адаптивными упражнениями и интервальным
повторением. Результат этого этапа — методическая и техническая спецификация,
пригодная для прямой реализации AI-агентом.

## 1. Ключевые решения, принятые по итогам исследования

Подробное обоснование каждого — в `docs/RESEARCH.md`. Здесь — только решения.

| # | Решение | Причина |
|---|---|---|
| D1 | Источник истины по требованиям экзамена — **Dz.U. 2018 poz. 1386, załącznik nr 1, część II, rozdz. E** (консолидированный текст rozporządzenia от 26.02.2016). Не блоги, не курсы. | Это нормативный акт; всё остальное — его пересказ, местами неточный |
| D2 | Целевая функция программы — **максимизировать минимальный модуль**, а не средний балл | §23 ust. 1 pkt 1 lit. b: для B1 нужно ≥50% **в каждом** из 4 письменных модулей **и** в устной части. Проваленный модуль = проваленный экзамен |
| D3 | Тайминги и баллы модулей **не хардкодить**, вынести в конфиг | Закон фиксирует только: вся письменная часть ≤190 мин, устная ≤15 мин, порог 50%. Поминутная раскладка и баллы задаются на листе каждой сессии |
| D4 | День 1 — **диагностика**, дальше три входных трека (A0 / A2 / B1−) | 15 мин/день от абсолютного нуля до B1 за 182 дня — нереалистично (см. D9). От A2 — реалистично |
| D5 | FSRS применяется **только к лексике и к декларативным карточкам правил**. Освоение грамматики как навыка моделируется отдельно (mastery-модель на базе доли ошибок) | FSRS моделирует забывание одного элемента. Правило — это навык, применяемый к множеству элементов; его «забывание» наблюдается через ошибки в разных упражнениях, а не через один отзыв |
| D6 | `ts-fsrs` пинится на **5.4.2** (MIT, Node ≥20, 0 зависимостей), API `fsrs()` / `createEmptyCard()` / `repeat()` / `next()` | v6 в npm только в бете (`6.0.0-beta.15`); README на GitHub описывает именно v6 — его API (`DefaultScheduler()`) в стабильной ветке нет |
| D7 | Морфология (склонение/спряжение) генерируется из **Morfeusz 2 + SGJP**, лицензия 2-clause BSD | Единственный крупный ресурс с явным разрешением на коммерческое использование. Снимает необходимость руками размечать 2500 слов |
| D8 | Словарь пишется **свой**. Wiktionary/Kaikki — только как справочник при составлении, не как импортируемая база | CC BY-SA 4.0 — share-alike заражает производную базу. Для закрытого продукта это блокер |
| D9 | Явно зафиксировать предел: 182 × 15 мин = **45,5 часов**. Cambridge оценивает путь до B1 в ~350–400 guided learning hours | Обещать B1 с нуля за 45 часов нельзя. Что 45 часов реально дают — расписано в `docs/CURRICULUM.md`, раздел «Реалистичность» |
| D10 | Контент — **JSON в `data/`**, Markdown — только схемы, правила и объяснения | 182 дня × 12 полей + ~2500 словарных статей в прозе нечитаемы и не импортируются. Markdown-таблица на 182 дня генерируется из JSON |
| D11 | `b1ready.pl` из ТЗ **исключён** | Домен не резолвится (NXDOMAIN), в поиске отсутствует. Замены: b1polski.pl, polingo.com.pl, hellopolish.pl, polishlanguage.online |
| D12 | Слова и фразы озвучиваются **браузерным TTS**. Предгенерация файлов — апгрейд v2, не блокер MVP | В приложении есть личный словарь и расширение: для слова, добавленного пользователем, предгенерация физически невозможна. Раз синтез всё равно в системе — дублировать его конвейером на 2500 файлов в MVP незачем |
| D13 | Материалы для **аудирования** — только предгенерированные файлы. Исключений нет | Нужны 2+ голоса в диалоге, одинаковый для всех темп, воспроизводимость и тестируемость. Модуль весит 40 баллов и имеет отдельный порог — единственное место, где на звуке экономить нельзя |
| D14 | Источник звука фиксируется **в данных** (`audio.source`), не в коде плеера | Переход MVP → v2 (device-tts → записи носителей) становится правкой `vocabulary.json` без изменений в коде |
| D15 | Архитектура **многоязычная с первого дня**: три независимые оси — `targetLanguage`, `sourceLanguage`, `goal` | Запрос на расширение на другие языки. Переделывать схему потом дороже, чем заложить сейчас: отличие в основном в том, чтобы не писать колонку `translation_ru` |
| D16 | Языковая специфика изолируется в `LanguagePlugin`; `packages/engine` не содержит ни одного `if (lang === 'pl')` | Критерий приёмки: добавление нового языка не меняет ни строки в движке. Проверяется линтером (запрет импорта `lang-*` из `engine`) |
| D17 | **Бэкенда нет.** Local-first: контент — статические JSON, данные пользователя — IndexedDB (Dexie), FSRS считается на клиенте. Next в режиме `output: 'export'` | Решение заказчика. Postgres + Drizzle появляются только под синхронизацию между устройствами; имена таблиц совпадают, миграция — замена слоя доступа |
| D18 | Стек: Next **16.4.3**, React **19.3.1**, Tailwind **4.3.3**, Dexie **4.4.7**, zustand **5.0.16**, `@serwist/next` **9.5.13** | Проверено по npm 2026-10-24. Dexie + `useLiveQuery` + zustand переносятся из EngTutor как проверенные решения. `next-pwa` мёртв с 2022 |
| D19 | i18n — `next-intl` **4.14.9**, локаль хранится **в настройках, не в URL** | Установленное PWA: адресной строки пользователь не видит. URL-локали усложнили бы статический экспорт без выгоды. Лендинг при появлении получит их отдельно |
| D20 | UI — примитивы `radix-ui` **1.8.1** + `tailwind-variants` **3.3.1**, shadcn/ui как источник для копирования. Не монолитная библиотека | Нужно 6 примитивов; остальной UI нестандартный (карточки упражнений, карта компетенций). Mantine/MUI пришлось бы переопределять. Base UI с декабря 2025 так и не вышел из RC |
| D21 | Инкапсуляция стилей: Tailwind-классы **только внутри `packages/ui`**, наружу — семантические пропсы. `className` снаружи разрешён только для позиционирования | Иначе простыни классов расползаются по экранам и расходятся при копировании. Правила R1–R7 в `DEV_RULES.md`, проверяются линтером и скриптом |
| D22 | Morfeusz **предрассчитывается** в таблицы форм на этапе сборки | Нативная библиотека, в браузере не запускается. Без бэкенда остаётся только предрасчёт: для 2500 лемм это мегабайты |

## 5. Главный риск

**Аудирование.** 40 баллов из ~170 письменных, порог 50% отдельно по модулю,
а стандарт прямо требует оригинальных, неадаптированных записей в нормальном
темпе. Это единственная компетенция, которую нельзя натренировать текстовыми
упражнениями, и она плохо помещается в 15 минут в день. Если программа где-то
и провалится — провалится здесь. Решение вынесено в отдельный раздел
`docs/CURRICULUM.md` («Аудирование как узкое место») и в опциональные блоки
сверх 15-минутного лимита.
