# EXERCISE_ENGINE.md — движок упражнений

Семь типов упражнений, генерация из настоящих парадигм и разбор ошибок.

Реализация — `packages/engine/src/exercises/`, **47 тестов** в сумме с
остальным движком.

---

## 1. Главная идея: дистракторы из настоящей парадигмы

Обычный генератор карточек подставляет случайные неверные варианты. Это
учит узнавать мусор, а не различать формы.

```
❌ случайные дистракторы        ✅ формы того же слова
   ręka → rąk                      ręka → rąk
         dziękuję                        ręce
         samolot                         rękami
         gazeta                          ręką
```

Второй вариант — это ровно то, что проверяет модуль
`Poprawność gramatyczna`: экзаменуемый должен различать формы одного
слова, а не отличать слово от другого слова.

Источник форм — `content/pl-b1-ru/morphology.json`, 311 лемм и
**8316 форм**, извлечённых из словаря SGJP.

### Откуда берётся морфология

Morfeusz — нативная библиотека, в браузере не работает, а бэкенда у нас
нет. Но SGJP публикует тот же словарь **простым текстом**:

```
rąk      ręka    subst:pl:gen:f          nazwa_pospolita  anat.
ręce     ręka    subst:pl:nom.acc.voc:f  nazwa_pospolita  anat.
rękę     ręka    subst:sg:acc:f          nazwa_pospolita  anat.
```

```bash
# 41 МБ, в репозиторий не кладём
node scripts/build-morphology.mjs ~/Downloads/sgjp-20261018.tab.gz
```

Скрипт просматривает 7,4 млн строк, вырезает наши ~370 лемм и
складывает готовые таблицы в контент — 349 КБ. В рантайме остаётся
просмотр объекта, никакой морфологии.

⚠️ **Лицензия 2-clause BSD** требует сохранить копирайт. Он переносится в
поле `_license` выходного файла и обязан быть показан в «О приложении».

Две детали, на которых это ломалось:

- SGJP различает омонимы суффиксом: `czas:S` — существительное,
  `czas:V` — предикатив, `miasto:P` — предлог. Без отсечения суффикса
  терялось 20 лемм
- теги вида `subst:pl:nom.acc.voc:f` раскрываются в три отдельных падежа

Из 370 запрошенных лемм найдено 311. Остальные 59 — союзы, предлоги и
наречия, у которых парадигмы нет по определению.

## 2. Семь типов упражнений

| Тип | Режим | Сложность | Модуль | Что тренирует |
|---|---|---|---|---|
| `translate-recognition` | выбор | 1 | reading | pl → ru |
| `translate-production` | выбор | 2 | writing | ru → pl |
| `spelling` | сборка | 3 | writing | **диакритика** |
| `choose-form` | выбор | 3 | grammar | закрытое задание экзамена |
| `gap-fill` | выбор | 4 | grammar | форма в контексте |
| `false-friend-contrast` | выбор | 4 | reading | перебить ложную ассоциацию |
| `inflect` | ввод | 5 | grammar | **открытое задание экзамена** |

Сложность — не украшение: она идёт в mastery-модель как вес наблюдения.
Верный ответ на `inflect` (5) говорит о владении больше, чем верный выбор
из четырёх вариантов (3).

### Почему `inflect` самый дорогой

NAWA отмечает, что за одни закрытые задания можно взять 15–17,5 из 30 —
формально порог. Но открытые задания имеют большую различительную силу и
оцениваются строго: понятные, но грамматически неверные формы баллов не
получают. Поэтому в занятии закрытые и открытые **чередуются**.

### Ложный друг — отдельный тип, не карточка

```
Осторожно: ложный друг
         sklep
   ○ склеп        ← то, чем кажется
   ● магазин      ← верно
   ○ grobowiec    ← то, как сказать «склеп»

→ «склеп» по-польски — grobowiec
```

Обычная карточка здесь не работает: ошибка не в незнании, а в **ложном
знании**, которое подкрепляется родным языком каждый день. Нужен активный
контраст.

### Сборка по буквам — ради диакритики

`może` / `morze`, `laska` / `łaska` — разница в одном знаке. Упражнение
генерируется только для слов с диакритикой и длиной до 12 букв.

## 3. Детерминированность

Все генераторы принимают `seed`:

```ts
translateRecognition(word, pool, { seed: hashString(word.id) })
```

Один вход — одно и то же упражнение. Без этого упражнения невозможно
тестировать, а пользователь получал бы разный порядок вариантов при
каждом ререндере.

⚠️ `Math.random()` в генераторах запрещён.

## 4. Вырожденные упражнения отсекаются

Баг, пойманный на живом прогоне:

```
ПОСТАВЬТЕ В ИМЕНИТЕЛЬНОМ ПАДЕЖЕ, ЕД. Ч.
            miły
   ○ miły  ← ответ написан в самом задании
```

Если целевая форма совпадает с начальной, упражнения нет. Генератор
возвращает `null`, вызывающий берёт следующий тег. Покрыто тестом.

## 5. Разбор ошибки: не все ошибки одинаковы

```ts
type ErrorKind = 'diacritic' | 'typo' | 'wrong-form' | 'wrong-word'
```

| Ответ на «родительный мн. ч. от ręka» | Классификация | Что говорим |
|---|---|---|
| `rąk` | верно | — |
| `RĄK ` | верно | регистр и пробелы не считаются |
| `rak` | `diacritic` | «Форма верная, но потеряна диакритика — на экзамене это ошибка» |
| `rąkk` | `typo` | «Опечатка» |
| `ręce` | `wrong-form` | «Не та форма» |

Разделение `diacritic` и `wrong-form` принципиально: в первом случае
человек **знает грамматику** и промахнулся по орфографии, во втором — не
знает. Это разные пробелы и разные дриллы, хотя на экзамене обе ошибки
стоят одинаково.

Расстояние Левенштейна ≤ 1 от принятого ответа — опечатка, больше —
неверная форма.

## 6. Связь правил и форм — в языковом плагине

Движок обращается с тегами как с непрозрачными строками (R8). Расшифровка
и связь «правило → теги» живут в `apps/web/lib/lang-pl/tags.ts`:

```ts
export const RULE_TO_TAGS = {
  'pl.gram.c-gen-pl':  ['subst:pl:gen'],
  'pl.gram.v-past-pl': ['praet:pl'],
  'pl.gram.c-loc':     ['subst:sg:loc', 'subst:pl:loc'],
}

labelTag('subst:pl:gen:f')  // «Поставьте в родительном падеже, мн. ч.»
```

Для немецкого будет свой модуль с той же сигнатурой — движок не меняется.

## 7. Сборка занятия

`apps/web/lib/engine/exercises.ts` соединяет план дня, словарь,
морфологию и плагин:

**На новое слово:**
1. контраст (если ложный друг) либо узнавание
2. продукция — **только для ядра**; тематика остаётся на узнавании
   (`VOCABULARY.md` §2)
3. сборка по буквам — если в слове есть диакритика

**На правило дня:** до 3 упражнений на уже введённой лексике, закрытые и
открытые вперемешку.

Результат живого прогона: день 5 дал **12 шагов** вместо 8 — ввод слов,
узнавание, сборка по буквам и `choose-form` на `pl.gram.gender`.

## 8. Куда уходит результат

Одно упражнение обновляет **две модели сразу**:

```
ответ
  ├─→ FSRS: карточка lexeme-recognition или lexeme-production
  │          (какая — зависит от типа упражнения)
  └─→ mastery: все правила из ex.grammarRuleIds,
               с весом = ex.difficulty
```

Это ключевое отличие от flashcard-приложения: упражнение на склонение
существительного — одновременно отзыв по лексической карточке и
наблюдение по грамматическому правилу.

## 9. Чего ещё нет

| | Почему |
|---|---|
| Трансформации (утв. → отриц., ед. → мн.) | Нужны шаблоны предложений, не только формы |
| Исправление ошибки в предложении | Нужен корпус типичных ошибок русскоязычных |
| Задания на чтение и аудирование | Нужны тексты и записи — отдельная контентная задача |
| Письмо и говорение | Оценка по пяти критериям, нужна LLM-рубрика |
| Генерация предложений для `gap-fill` | Сейчас функция есть, но предложения не написаны |

Первые два закрываются расширением контента, не кодом. Последние три —
отдельные этапы.
