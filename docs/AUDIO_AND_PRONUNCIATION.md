# AUDIO_AND_PRONUNCIATION.md — звук в приложении

Два разных вопроса, которые постоянно смешивают:

1. **Воспроизведение** — как дать пользователю услышать правильное произношение
2. **Оценка** — как проверить, правильно ли произносит сам пользователь

Плюс третий, скрытый и самый важный для экзамена: **аудирование** — это не
отдельные слова, а связная речь. Про него §5.

Проверено 2026-10-24.

---

## 0. Чего НЕТ (снимаем недоразумение)

Готовой базы «слово + перевод на русский + аудио + уровень B1», которую можно
взять и подключить, **не существует**. Ни бесплатной, ни платной под свободной
лицензией. Три компонента живут в трёх разных местах, и собирать их нужно
самому:

| Нужно | Где есть | Лицензия | Готово к использованию? |
|---|---|---|---|
| Словоформы, парадигмы, теги | **Morfeusz 2 + SGJP** | 2-clause BSD | ✅ Да, целиком |
| Переводы на русский | Wiktionary / Kaikki, словари | CC BY-SA / проприетарно | ⚠️ Только как справочник |
| Аудио отдельных слов | **Wikimedia Commons** (Lingua Libre и др.) | CC BY-SA 4.0 | ✅ Да, но с пробелами |
| Аудио связной речи (диалоги, объявления) | **Нигде** | — | ❌ Генерировать или записывать |
| Привязка к уровню B1 и к темам экзамена | **Нигде** | — | ❌ Делать самому |

**Morfeusz — это морфологический анализатор, а не словарь и не аудио.** Он
отвечает на вопрос «какие формы у слова `ręka`» (и отвечает отлично —
1116 парадигм, 4,3 млн словоформ). Он ничего не знает ни про перевод, ни про
звук, ни про то, нужно ли это слово на B1.

## 1. Аудио отдельных слов: что реально доступно

### 1.1. Объём

Проверено через Commons API:

| Категория | Файлов | Формат | Схема имени |
|---|---|---|---|
| `Lingua Libre pronunciation-pol` | **97 546** | `.wav` | `LL-Q809 (pol)-<диктор>-<слово>.wav` |
| `Polish pronunciation` | **24 143** | `.ogg` | `Pl-<слово>.ogg` |

Это записи живых носителей, не синтез.

### 1.2. Реальное покрытие

Я проверил выборку из 30 слов уровня B1 на **точное** совпадение леммы (не
«слово встречается внутри словосочетания», а именно отдельная лемма):

```
Точное совпадение:  26/30  (86%)
Не найдено:          4/30  — wynajmować, sprawozdanie, gdyby, żeby
```

Закономерность в пробелах видна: не хватает **служебных слов** (`gdyby`,
`żeby`) и части **производных/видовых форм** (`wynajmować` при наличии
`wynająć`). Для знаменательной лексики покрытие близко к полному.

**[ОЦЕНКА]** На словаре в 2500 единиц ожидаемо 80–90% покрытия, то есть
250–500 слов придётся закрывать синтезом. Точную цифру нужно померить скриптом
по финальному словарю — это задача этапа 3.

### 1.3. Лицензия: что на самом деле разрешено

Это важно уточнить, потому что в `RESEARCH.md` §6.2 я написал про share-alike
слишком широко — там речь шла о **тексте** Wiktionary, и к аудио это
применяется иначе.

**[ИСТОЧНИК]** По [CC FAQ](https://creativecommons.org/faq/):

- Включение **неизменённого** произведения CC BY-SA в более крупный сборник
  (collection) **не требует** лицензировать весь сборник под BY-SA.
  Сборник ≠ производное произведение
- ShareAlike срабатывает только на **Adapted Material** — изменённый материал
- **Смена формата не является адаптацией**: лицензия прямо разрешает
  использование «in any media or format»

**Практический вывод:**

| Действие | Статус |
|---|---|
| Положить `.ogg` с Commons в приложение как есть | ✅ Сборник. Приложение не становится BY-SA |
| Перекодировать `.wav` → `.opus` для веса | ✅ Смена формата, не адаптация |
| Обрезать тишину, нормализовать громкость | ⚠️ Спорно, вероятно адаптация → сам файл остаётся BY-SA |
| Склеить несколько записей в диалог | ⚠️ Адаптация → результат под BY-SA |
| Не указать авторов записей | ❌ Нарушение в любом случае |

**Атрибуция обязательна всегда.** Нужен экран «Источники» со списком дикторов
и ссылками на файлы Commons. Это не формальность: у Lingua Libre у каждой
записи есть конкретный автор.

⚠️ Перед коммерческим релизом это стоит показать юристу. Я излагаю прочтение
лицензии, а не даю юридическое заключение.

### 1.4. Нужно ли хранить у себя?

**Да, обязательно.** Хотлинк на Commons — плохая идея по четырём причинам:

1. **Этикет и лимиты.** Wikimedia просит не использовать их как CDN. Я уже
   поймал `HTTP 429 Too Many Requests` на 8-м запросе подряд при обычном
   исследовании
2. **Офлайн.** PWA без офлайн-аудио бесполезно в метро — а 15 минут в день это
   ровно сценарий метро
3. **Консистентность.** На Commons у одного слова может быть запись Olaf'а, у
   следующего — Gower'а, у третьего — Poemat'а. Разные голоса, разная
   громкость, разная манера. Для курса это звучит рвано
4. **Стабильность.** Файлы на Commons переименовывают и удаляют

**Размер хранилища — не проблема.** 2500 слов × ~1,5 с × opus 24 kbps
≈ **12–15 МБ**. Это меньше одной фотографии с телефона.

## 2. Три варианта озвучки: сравнение

### Вариант A — Web Speech API браузера

```js
const u = new SpeechSynthesisUtterance('mieszkanie')
u.lang = 'pl-PL'
speechSynthesis.speak(u)
```

| | |
|---|---|
| ✅ | Ноль стоимости, ноль хранилища, ноль конвейера сборки, две строки кода |
| ✅ | **Покрытие 100% по определению** — включая слова, которых нет в курсе |
| ✅ | **Единственный способ озвучить личный словарь.** Слово, которое пользователь добавил через расширение минуту назад, предгенерировать невозможно |
| ✅ | Ноль лицензионных обязательств и атрибуций |
| ✅ | Для нового языка не нужно ничего, кроме смены тега `lang` |
| ✅ | Качество на мейнстримных платформах сейчас приличное: нейронные голоса в Google TTS (Android/Chrome), Zosia на Apple, Paulina на Windows |
| ❌ | **Голоса зависят от ОС.** На Linux польского часто нет вообще; на старых Android — устаревший движок |
| ❌ | **Недетерминированно.** Один урок звучит по-разному у разных людей. Автотесты на звук невозможны |
| ❌ | iOS Safari требует жеста пользователя; офлайн-поведение зависит от того, скачал ли пользователь голос |
| ❌ | Один голос на всё. Диалог двух собеседников не сделать |
| ❌ | Нет контроля темпа и пауз на уровне, нужном для экзаменационного аудирования |

**Про Siri отдельно.** Голос Siri для сторонних приложений **недоступен** —
Apple закрыла его намеренно, чтобы приложения не могли выдавать себя за Siri.
`AVSpeechSynthesizer` (и Web Speech API поверх него) отдаёт обычные системные
голоса. Пользователь может доустановить «enhanced» и «premium» варианты в
Настройках → Универсальный доступ, и тогда они станут доступны приложению —
но заставить его это сделать нельзя.
**[ИСТОЧНИК]** Плюс в iOS 26 есть зарегистрированный баг: `AVSpeechSynthesisVoice`
игнорирует выбранный пользователем голос. Хорошая иллюстрация того, что на
платформенный TTS нельзя закладываться как на детерминированный компонент.

**Вердикт: не fallback, а основной механизм — но не везде.** См. §3.

### Вариант B — записи носителей с Commons

| | |
|---|---|
| ✅ | Живые носители, настоящая интонация |
| ✅ | Бесплатно, лицензия позволяет |
| ✅ | Детерминировано, работает офлайн |
| ❌ | Покрытие ~86%, дыры в служебных словах |
| ❌ | Разные дикторы → рваное звучание |
| ❌ | Только отдельные слова. Фраз и диалогов нет |
| ❌ | Нужна обязательная атрибуция |

### Вариант C — нейросетевой TTS, сгенерированный на этапе сборки

Ключевая идея: **генерировать не в рантайме, а один раз при сборке контента**,
и класть результат в репозиторий как файлы.

| | |
|---|---|
| ✅ | Покрытие 100%: слова, словосочетания, примеры, диалоги, объявления |
| ✅ | Один голос на весь курс (или 2–3 ролями для диалогов) |
| ✅ | Детерминировано, офлайн, тестируемо |
| ✅ | Платишь один раз за генерацию, а не за каждого пользователя |
| ✅ | Можно управлять темпом: медленно для разбора, нормально для аудирования |
| ❌ | Разовые затраты на генерацию |
| ❌ | Синтез всё же не равен живой речи — и это принципиально для модуля
аудирования, см. §5 |

**Варианты движка:**

- **Коммерческие облачные** (Azure Neural, Google, ElevenLabs, OpenAI) —
  лучшее качество, pl-PL есть у всех. Платно за символ. ⚠️ Цены проверять
  актуальные, я их не верифицировал
- **Piper (локально, бесплатно)** — VITS-модели в ONNX, есть голоса `pl_PL`
  (Bass, Mc Speech, Darkman, Gosia). Работает на Raspberry Pi, меньше 1 ГБ.
  **[ИСТОЧНИК]** Лицензия изменилась: исходный `rhasspy/piper` заархивирован
  под MIT в октябре 2025, активная разработка — `OHF-Voice/piper1-gpl` под
  **GPL-3.0-or-later**. Для генерации на этапе сборки GPL не проблема: вы не
  поставляете сам движок пользователю, только аудиофайлы. Качество «medium»
  ниже коммерческого, но для отдельных слов достаточно

## 3. Рекомендуемая стратегия: решает не уровень качества, а тип контента

Главная ошибка — выбирать «один движок для всего звука». Правильное деление
проходит **не по качеству, а по тому, известен ли текст заранее и сколько он
весит в экзамене.**

| Тип контента | Текст известен при сборке? | Цена ошибки | Механизм |
|---|---|---|---|
| Слово из личного словаря, добавленное пользователем | ❌ Нет | низкая | **Браузерный TTS. Единственный вариант** |
| Слово из курса (2500 единиц) | ✅ Да | низкая | **Браузерный TTS в MVP**, предгенерация — апгрейд v2 |
| Пример употребления, фраза | ✅ Да | средняя | Браузерный TTS в MVP |
| **Диалог, объявление, монолог для модуля аудирования** | ✅ Да | **высокая: 40 баллов и отдельный порог** | **Только предгенерация. Не обсуждается** |

### Почему личный словарь закрывает спор

В приложении есть персональный словарь и Chrome-расширение: пользователь
выделяет польское слово на любой странице и кладёт его к себе. Для такого слова
**предгенерация физически невозможна** — вы не знаете заранее, что он выделит.
Значит браузерный TTS в системе будет в любом случае. А раз он всё равно есть
и работает — тащить параллельно конвейер из 2500 файлов ради тех же слов в
MVP незачем.

### Почему аудирование — исключение

Здесь предгенерация обязательна, и причины не про качество голоса:

1. **Два и более голоса в диалоге.** `SpeechSynthesisUtterance` этого не умеет
   нормально: голоса на устройстве пользователя могут не содержать двух польских
2. **Все должны слышать одно и то же.** Это тестовый материал. Если у одного
   пользователя запись звучит быстрее, его результат несопоставим
3. **Контроль темпа и пауз.** Экзамен идёт в нормальном, не учебном темпе.
   Задание должно воспроизводиться дважды с выверенной паузой
4. **Тестируемость.** Задание с пропусками нужно проверять в CI на фиксированном
   аудио
5. **Это модуль с самым высоким весом и отдельным порогом.** Единственное место,
   где экономить на звуке нельзя

### Итоговое решение

```
Слова и фразы   →  Web Speech API (lang = целевой язык)
                   + опционально запись носителя с Commons,
                     если она есть и мы хотим «живой» голос
                   → предгенерация TTS как апгрейд v2, не блокер MVP

Аудирование     →  предгенерированные файлы, 2+ голоса, фиксированный темп
                   → в репозитории, офлайн, под тестами
```

Это меняет приоритеты разработки: **конвейер `build-audio` переезжает из MVP
в v2**, а в MVP остаётся только генерация материалов для аудирования — их
десятки, а не тысячи.

### Если всё-таки делать предгенерацию слов (v2)

Тогда работает трёхуровневая схема с приоритетом живого голоса:

```
Tier 1  Запись носителя с Commons, точное совпадение леммы   ~85% словаря
Tier 2  Нейро-TTS на этапе сборки                            оставшиеся ~15%
Tier 3  Web Speech API                                       аварийный fallback
```

Решение принимается **на этапе сборки**, не в рантайме. В `vocabulary.json` у
каждой единицы лежит готовая ссылка:

```jsonc
{
  "id": "pl.mieszkanie",
  "lemma": "mieszkanie",
  "audio": {
    "source": "commons",
    "file": "Pl-mieszkanie.ogg",
    "localPath": "audio/pl/words/mieszkanie.opus",
    "attribution": {
      "author": "…",
      "license": "CC BY-SA 4.0",
      "url": "https://commons.wikimedia.org/wiki/File:Pl-mieszkanie.ogg"
    }
  }
}
```

```jsonc
{
  "id": "pl.wynajmowac",
  "lemma": "wynajmować",
  "audio": {
    "source": "tts",
    "engine": "piper/pl_PL-gosia-medium",
    "generatedAt": "2026-10-24",
    "localPath": "audio/pl/words/wynajmowac.opus"
  }
}
```

В MVP у большинства единиц поле будет просто:

```jsonc
{ "id": "pl.gdyby", "lemma": "gdyby", "audio": { "source": "device-tts" } }
```

Приложение смотрит на `source`: `device-tts` → синтез на устройстве,
`commons`/`tts` → проиграть `localPath` (и показать атрибуцию для `commons`).
Логика выбора источника в рантайм не попадает — она зафиксирована в данных.
Это и позволяет перейти от MVP к v2 **без единой правки в коде плеера**:
меняется только содержимое `vocabulary.json`.

### Конвейер сборки (v2, не нужен для MVP)

```
scripts/build-audio.ts
  1. читает vocabulary.json
  2. для каждой леммы ищет точное совпадение в Commons API
     (кэш ответов на диске — Commons отдаёт 429 на частых запросах)
  3. найдено   → скачать, перекодировать в opus 24 kbps mono, записать атрибуцию
     не найдено → поставить в очередь TTS
  4. прогнать очередь TTS батчем
  5. нормализовать громкость всех файлов к одному уровню (EBU R128)
  6. записать audio-manifest.json + attributions.json
```

Запускается вручную при изменении словаря, результат коммитится. В CI это
гонять не нужно.

## 3bis. Как это воспроизводится технически

Три механизма, по типу контента.

### A. Слово или предложение — синтез на устройстве

```ts
// packages/engine/src/speech/device-tts.ts — языконезависимо
type SpeakOpts = { lang: string; rate?: number; voiceURI?: string }

let voicesReady: Promise<SpeechSynthesisVoice[]> | null = null

/** getVoices() на первом вызове часто пуст — список приезжает асинхронно. */
function loadVoices(): Promise<SpeechSynthesisVoice[]> {
  if (voicesReady) return voicesReady
  voicesReady = new Promise((resolve) => {
    const got = speechSynthesis.getVoices()
    if (got.length) return resolve(got)
    speechSynthesis.addEventListener(
      'voiceschanged',
      () => resolve(speechSynthesis.getVoices()),
      { once: true },
    )
    // Safari иногда не стреляет voiceschanged вовсе
    setTimeout(() => resolve(speechSynthesis.getVoices()), 1000)
  })
  return voicesReady
}

export async function pickVoice(lang: string) {
  const voices = await loadVoices()
  const base = lang.split('-')[0]                     // 'pl-PL' → 'pl'
  return (
    voices.find((v) => v.lang.replace('_', '-') === lang) ??
    voices.find((v) => v.lang.replace('_', '-').startsWith(base)) ??
    null
  )
}

export async function speak(text: string, opts: SpeakOpts): Promise<void> {
  if (!('speechSynthesis' in window)) throw new NoSpeechSupport()
  const voice = await pickVoice(opts.lang)
  if (!voice) throw new NoVoiceForLanguage(opts.lang)   // ← важно: обработать в UI

  const u = new SpeechSynthesisUtterance(text)
  u.voice = voice
  u.lang = opts.lang
  u.rate = opts.rate ?? 0.95                            // 0.6 для режима «медленно»

  speechSynthesis.cancel()                              // снять предыдущее
  return new Promise((resolve, reject) => {
    u.onend = () => resolve()
    u.onerror = (e) => reject(e)
    speechSynthesis.speak(u)
  })
}
```

Предложения озвучиваются **тем же вызовом** — это просто более длинная строка.
Ничего отдельного для фраз не нужно.

**Грабли, которые обязательно всплывут:**

| Проблема | Решение |
|---|---|
| `getVoices()` возвращает `[]` при первом вызове | ждать `voiceschanged`, плюс таймаут для Safari |
| iOS требует жест пользователя | первый `speak()` — только из обработчика клика. «Прогреть» синтез пустой фразой при первом тапе в сессии |
| На устройстве нет голоса целевого языка | явная ошибка `NoVoiceForLanguage` → UI показывает подсказку, как доустановить голос; упражнение на аудирование — скрыть |
| Повторный тап накладывает речь | `speechSynthesis.cancel()` перед каждым `speak()` |
| Android Chrome обрывает речь длиннее ~15 с | резать длинный текст по предложениям и ставить в очередь |
| Нет события окончания | таймаут-страховка: `текст.length × ~60 мс` |

### B. Слово с записью носителя — обычный `<audio>`

Если у единицы в контенте есть `audio.localPath`:

```ts
export async function playFile(src: string): Promise<void> {
  const el = new Audio(src)
  await el.play()           // бросит, если автоплей заблокирован
}
```

Поверх — та же схема fallback, что уже написана в EngTutor
(`apps/pwa/src/api/tts.ts`): пробуем файл, при ошибке уходим в синтез.

### C. Аудирование — предгенерированный файл, без вариантов

Диалог или объявление — это **один готовый `.opus`**, лежащий в контенте:

```jsonc
{
  "id": "pl-b1.listen.d034",
  "day": 34,
  "kind": "dialogue",
  "audio": "audio/pl/listening/d034.opus",
  "durationSec": 48,
  "playbacks": 2,
  "pauseBetweenSec": 15,
  "transcript": "…",            // показывается ТОЛЬКО после ответа
  "tasks": [ /* … */ ]
}
```

Плеер здесь — не «озвучка», а **контроллер задания**: два проигрывания,
выверенная пауза, запрет перемотки, транскрипт открывается после ответа.
Синтезом на устройстве это не реализуется в принципе — нужны два голоса,
одинаковый для всех темп и воспроизводимость.

### Единая точка входа

```ts
// то, что вызывает UI — ему всё равно, откуда звук
export async function pronounce(item: Pronounceable, mode: 'normal' | 'slow') {
  const rate = mode === 'slow' ? 0.6 : 0.95
  if (item.audio?.localPath) {
    try { return await playFile(item.audio.localPath) } catch { /* вниз */ }
  }
  return speak(item.text, { lang: item.langBcp47, rate })
}
```

`langBcp47` приходит из `LanguagePlugin.audio.bcp47` — поэтому при добавлении
нового языка этот код не меняется.

## 3ter. Что нужно, чтобы произносилось ВЕРНО и на НУЖНОМ языке

Семь независимых мест, где это ломается. Перечислены в порядке частоты.

### 1. Диакритика в данных

Самая частая и самая глупая поломка. Если в словаре лежит `zyc` вместо `żyć`,
`reka` вместо `ręka`, `swiat` вместо `świat` — синтез прочитает ровно то, что
написано, и это будет неправильное слово, а не акцент.

```ts
// валидатор контента, гоняется в CI
const PL_DIACRITICS = /[ąćęłńóśźż]/i
// эвристика: в польском тексте длиннее ~40 символов диакритика обязана быть
if (text.length > 40 && !PL_DIACRITICS.test(text)) {
  throw new Error(`Похоже на текст без диакритики: ${text}`)
}
```

Плюс запрет визуально похожих символов из других алфавитов: кириллическая `о`
в польском слове сломает и синтез, и поиск, и сравнение ответа.

### 2. Явный выбор голоса, а не только `lang`

**Главная причина «читает по-польски с английским акцентом».** Если задать
только `u.lang = 'pl-PL'`, но польского голоса в системе нет, браузер
молча возьмёт голос по умолчанию и прочитает польский текст по правилам
английского или русского.

```ts
// ❌ так — тихая деградация в неверный язык
const u = new SpeechSynthesisUtterance('mieszkanie')
u.lang = 'pl-PL'
speechSynthesis.speak(u)

// ✅ так — голос выбран явно, отсутствие обработано
const voice = await pickVoice('pl-PL')
if (!voice) throw new NoVoiceForLanguage('pl-PL')
u.voice = voice
u.lang = voice.lang
```

Нужно задавать **и `voice`, и `lang`**: часть движков игнорирует одно из двух.

### 3. Отсутствие голоса — это ошибка, а не тишина

Если польского голоса нет, нельзя ни молчать, ни читать чужим голосом.
Нужно показать пользователю, что делать:

| Платформа | Куда вести |
|---|---|
| iOS / macOS | Настройки → Универсальный доступ → Устный контент → Голоса → Польский |
| Windows | Параметры → Время и язык → Речь → Добавить голоса |
| Android | Настройки → Специальные возможности → Синтез речи → установить язык |
| Linux | чаще всего голоса нет вовсе → предложить предгенерированное аудио |

И отдельно: пока голоса нет, упражнения на слух нужно **скрывать**, а не
показывать сломанными.

### 4. Один utterance — один язык

В интерфейсе соседствуют русский и польский. Если озвучить «mieszkanie —
квартира» одной фразой, любой голос прочитает половину неправильно.

```ts
// ✅ две отдельные реплики, каждая со своим голосом
await speak('mieszkanie', { lang: 'pl-PL' })
await pause(400)
await speak('квартира',   { lang: 'ru-RU' })
```

Это, кстати, ещё один довод за многоязычную схему: `lang` берётся из
`targetLanguage` / `sourceLanguage` записи, а не из константы.

### 5. Нормализация текста перед синтезом

Синтез читает строку буквально. Всё, что не слово, нужно развернуть заранее:

| В данных | Что произойдёт | Что подать на синтез |
|---|---|---|
| `15 zł` | может прочитать «зэт эль» | `piętnaście złotych` |
| `np.` | «эн пэ кропка» | `na przykład` |
| `godz. 8:30` | непредсказуемо | `godzina ósma trzydzieści` |
| `ul. Piękna` | «у эл» | `ulica Piękna` |
| `3 Maja` | «три мая» ≠ `trzeciego maja` | развернуть по контексту |

Для учебного контента это решается просто: в данных у примера рядом с
`sentence` лежит необязательное поле `speakAs` — что именно подавать на синтез.
Пишется один раз при подготовке контента.

```jsonc
{
  "sentence": "Bilet kosztuje 15 zł.",
  "speakAs":  "Bilet kosztuje piętnaście złotych."
}
```

### 6. SSML в Web Speech использовать нельзя

**[ИСТОЧНИК]** По спецификации `SpeechSynthesisUtterance.text` может принимать
SSML, а устройства без поддержки должны теги вырезать. На практике
**ни один крупный браузер этого не делает**, а на macOS SSML
**зачитывается вслух как обычный текст** — пользователь услышит «speak phoneme
alphabet ipa».

Значит в браузерном синтезе недоступны `<phoneme>`, `<break>`, `<emphasis>`.
Управлять можно только `rate`, `pitch`, `volume` и разбиением на реплики.

SSML доступен в облачных TTS — и это ещё один аргумент за то, чтобы материалы
аудирования (где паузы и темп критичны) генерировать заранее, а не на
устройстве.

### 7. Как узнать, что произносится верно

Это и есть исходный вопрос, и честный ответ — **слепо доверять синтезу
нельзя**. Проверка двухуровневая.

**Уровень 1: автоматический round-trip, покрывает весь словарь**

```
текст → TTS → аудио → ASR (Whisper, pl) → текст' → сравнить с текстом
```

```ts
// scripts/verify-pronunciation.ts
for (const item of vocabulary) {
  const wav = await tts(item.speakAs ?? item.lemma, { lang: 'pl-PL' })
  const heard = await whisper(wav, { language: 'pl' })
  if (normalize(heard) !== normalize(item.lemma)) {
    report.push({ expected: item.lemma, heard })   // ← на ручную проверку
  }
}
```

Что это ловит:
- ✅ синтез взял голос не того языка — расхождение будет огромным
- ✅ слово искажено до неузнаваемости
- ✅ часть текста проглочена
- ✅ числа и сокращения прочитаны не так

Что это **не** ловит — и это важно понимать:
- ❌ **неверное ударение.** ASR распознает `uniwersytet` правильно независимо
  от того, куда синтез поставил ударение
- ❌ неестественная интонация
- ❌ смазанные носовые `ą`/`ę`

**Уровень 2: ручная проверка по списку рисков**

Автоматика не ловит просодию, поэтому носитель выборочно слушает — но не все
2500 слов, а целевой список. Для польского ударение регулярное (предпоследний
слог), поэтому проверять нужно ровно исключения, на которых TTS и спотыкается:

| Класс | Примеры |
|---|---|
| Заимствования на `-yka`/`-ika` | `matematyka`, `fizyka`, `gramatyka`, `muzyka` |
| Формы прошедшего времени мн. ч. | `poszliśmy`, `zrobiliście`, `byliśmy` |
| Сослагательное наклонение | `zrobilibyśmy`, `napisałbym` |
| Числительные | `czterysta`, `siedemset`, `dziewięćset` |
| Прочее | `uniwersytet`, `prezydent`, `okolica` |

Это несколько десятков слов, а не тысячи. Проверяются один раз на каждом
голосе и заносятся в список.

**Что делать с теми, где синтез ошибается:** для них взять запись носителя
с Commons (Tier 1) и зафиксировать в данных `audio.source = "commons"`.
Это ровно тот случай, ради которого гибридная схема и нужна.

### Сводный чек-лист

```
Данные
  ☐ диакритика на месте, валидатор в CI
  ☐ нет символов из чужих алфавитов
  ☐ speakAs заполнен там, где есть числа и сокращения

Код
  ☐ голос выбирается явно через getVoices(), не только lang
  ☐ задаются и voice, и lang
  ☐ отсутствие голоса → явная ошибка и подсказка, не тишина
  ☐ один utterance = один язык
  ☐ speechSynthesis.cancel() перед каждым воспроизведением
  ☐ никакого SSML в браузерном синтезе

Проверка
  ☐ round-trip TTS→Whisper по всему словарю, в CI
  ☐ ручная проверка списка ударных исключений на каждом голосе
  ☐ для проблемных слов — запись носителя вместо синтеза
```

## 4. Оценка произношения пользователя

Это отдельная задача, и к ней стоит подойти трезво.

### 4.1. Нужна ли она вообще

На экзамене произношение — **одна из пяти** позиций оценки устной части
(`sprawność komunikacyjna, wykonanie zadania, poprawność gramatyczna,
słownictwo, wymowa i intonacja`). Стандарт прямо допускает заметный родной
акцент, если он не мешает пониманию:

> Wpływ zasad wymowy języka rodzimego może być mocno odczuwalny, ale nie
> powinien w istotny sposób zakłócać zrozumienia wypowiedzi.

**[ОЦЕНКА]** Вывод: гнаться за фонетической точностью не нужно. Для
русскоязычного важнее три конкретные вещи, и они проверяются правилами, а не
нейросетью:

1. **Ударение на предпоследний слог** + исключения (`uniwersytet`,
   `poszliśmy`, `czterysta`, `matematyka`)
2. **Носовые `ą`, `ę`** — их русскоязычные стабильно теряют
3. **Шипящие ряды** `sz/ś`, `cz/ć`, `ż/ź`, `dż/dź` — главный источник
   неразличения

### 4.2. Технические варианты

| Подход | Польский | Комментарий |
|---|---|---|
| **Azure Pronunciation Assessment** | ✅ `pl-PL` поддержан | **[ИСТОЧНИК]** Даёт accuracy/fluency/completeness на уровне слова и фонемы. ⚠️ Но: названия фонем и слоговые группы документированы только для `en-US`, для польского имена фонем не поддержаны, и сами баллы некалиброваны. То есть «произнёс на 72» — число без понятной шкалы |
| **Whisper + сравнение с эталоном** | ✅ | Распознать речь пользователя и сравнить с целевой строкой. Ловит грубые ошибки (не то слово, пропуск), но не акцент |
| **Своя модель** | — | ❌ Не стоит. Обучение acoustic-модели для оценки произношения — это отдельный проект на месяцы, требующий размеченного корпуса речи неносителей. Несоразмерно задаче |

### 4.3. Рекомендация

**MVP: без автоматической оценки произношения.**

Вместо неё — цикл «послушай → повтори → сравни сам»: эталон, запись
пользователя, две дорожки рядом, пользователь слушает и сравнивает. Дёшево,
честно, и для 15-минутного формата этого достаточно.

**Фаза 2:** Whisper для проверки «сказал ли вообще то слово» — это даёт
объективный сигнал для устных упражнений без претензии на фонетику.

**Фаза 3, опционально:** Azure Pronunciation Assessment, если появится запрос.
Показывать как «ориентир», не как оценку, — из-за некалиброванности баллов.

## 5. Главное: аудирование — это не слова

Повторю, потому что это легко упустить за обсуждением озвучки словаря.

Модуль `Rozumienie ze słuchu` весит **40 баллов** — больше любого другого, и у
него отдельный порог 50%. И проверяет он **не** узнавание отдельных слов.

**[ЗАКОН]** Стандарт B1 требует понимания оригинальных текстов. **[ИСТОЧНИК]**
Пособие NAWA уточняет материал: оригинальные неадаптированные короткие
разговоры, объявления, фрагменты радио- и телепрограмм, в нормальном темпе,
в хороших, но не идеальных акустических условиях.

Озвучка 2500 слов не готовит к этому вообще никак. Нужны:

| Тип материала | Длина | Источник |
|---|---|---|
| Диалоги (2 голоса) | 30–60 с | TTS с разными голосами или записи |
| Объявления (вокзал, магазин, поликлиника) | 15–30 с | TTS |
| Монологи, сообщения на автоответчик | 30–45 с | TTS |
| Фрагменты новостей | 45–60 с | ⚠️ TTS плохо имитирует; нужна живая речь |
| Спонтанная речь с перебивами и заминками | — | ❌ TTS не воспроизводит |

**[ОЦЕНКА]** Честная граница: TTS закрывает учебное аудирование (диалоги,
объявления) на 70–80% задач. Оставшееся — спонтанная речь в нормальном
темпе — он не воспроизводит, а это ровно то, на чём люди проваливают модуль.

Поэтому в программе аудирование вынесено в **опциональный блок сверх
15 минут**: польское радио, подкасты, сериалы. Приложение должно отслеживать
его отдельно и честно говорить: «вы не слушали живую речь 12 дней, прогноз по
модулю аудирования — ниже порога».

## 6. Как это делают реальные приложения

**[ОЦЕНКА]** Обзор, чтобы было с чем сравнивать:

| Приложение | Подход к аудио |
|---|---|
| **Duolingo** | Нейро-TTS для почти всего контента (исторически Amazon Polly, сейчас собственные голоса). Живых записей мало. Масштабируется на десятки языков — это и есть причина выбора |
| **Babbel** | Профессиональные студийные записи носителей. Дорого, качественно, медленно расширяется |
| **Memrise** | Краудсорсинг: короткие видео носителей из реальной жизни. Их главный дифференциатор |
| **Forvo** | Краудсорсинг-произношение как сервис. Есть API, но **платный и проприетарный** — для встраивания в коммерческий продукт нужна лицензия |
| **Anki-колоды** | Как правило Commons/Forvo или TTS. То есть ровно то же, что предлагается здесь |
| **polishb1.pl** (конкурент) | Прямо пишут: AI-голоса, проверенные человеком |

Вывод: **для многоязычного продукта TTS-на-этапе-сборки — это индустриальный
стандарт**, а живые записи — премиальная надстройка. Выбранная здесь гибридная
схема (Commons как Tier 1, TTS как Tier 2) даёт живые голоса там, где они
бесплатны, и покрытие там, где их нет.

## 7. Что это значит для многоязычности

Эта стратегия не завязана на польский. Ровно та же трёхуровневая схема
работает для любого целевого языка:

- **Tier 1** — Lingua Libre покрывает 310+ языков. Для каждого меняется только
  код категории: `pol` → `deu` → `spa`
- **Tier 2** — у любого TTS-движка есть набор голосов; меняется идентификатор
  голоса в конфиге языкового пакета
- **Tier 3** — `SpeechSynthesisUtterance.lang` принимает любой BCP-47

Поэтому конфигурация аудио живёт **в языковом пакете**, а не в коде. См.
`ARCHITECTURE.md`, §3 — интерфейс `LanguagePlugin.audio`.
