# VOCABULARY.md — словарь

Принципы отбора, схема записи, разметка прозрачности и измеренный ответ на
главный вопрос: сколько слов реально помещается в 45,5 часа.

Данные — `content/pl-b1-ru/vocabulary.json`, **генерируются** из
`scripts/data/vocab-*.mjs`.

---

## 1. Главная идея: для русскоязычного слова стоят по-разному

Универсальный словарь «2500 слов уровня B1» для нашей аудитории — плохая
абстракция. `problem` и `wynajmować` стоят учащемуся принципиально разного
времени, и планировать их одинаково значит промахнуться в разы.

Поэтому каждая единица размечена полем **`transparency`**:

| Значение | Что это | Повторений | Пример |
|---|---|---|---|
| `transparent` | Узнаётся сразу, значение совпадает | **3** | `problem`, `szkoła`, `morze`, `brat` |
| `partial` | Узнаётся, но значение сдвинуто | **6** | `miasto` (город, не место), `godzina` (час) |
| `opaque` | Русский не помогает | **8** | `dziękuję`, `bardzo`, `zeszyt`, `pociąg` |
| `false-friend` | Узнаётся и понимается **неверно** | **10** | `sklep`, `dywan`, `uroda`, `zapomnieć` |

Ложный друг дороже непрозрачного слова: его мало выучить — нужно
**перебить уже существующую неверную ассоциацию**, а она подкрепляется
родным языком каждый день.

## 2. Модель стоимости

```
стоимость = ввод(20 с) + повторений × (узнавание 6 с + [воспроизведение 13 с])
```

Воспроизведение (`ru → pl`, с вводом или сборкой слова) тренируется не у
всех единиц, а только у **ядра**: служебные слова, глаголы, ложные друзья.
Тематическая лексика в основном остаётся на узнавании — для чтения и
аудирования этого достаточно, а на письме и в речи человек обходится
меньшим активным запасом.

```
Прозрачное, только узнавание:      20 + 3×6        =  38 с
Непрозрачное, только узнавание:    20 + 8×6        =  68 с
Непрозрачный глагол с продукцией:  20 + 8×(6+13)   = 172 с
Ложный друг с продукцией:          20 + 10×(6+13)  = 210 с
```

Модель живёт в `scripts/build-vocabulary.mjs` → `COST` и пересчитывается
при каждой сборке. Поменялись представления о темпе — поменялись числа,
и программа перестроилась сама.

## 3. Что измерено

Текущее ядро — **327 единиц**, отобранных вручную:

```
Прозрачность:
  transparent     146   45%
  opaque           75   23%
  partial          71   22%
  false-friend     35   11%

Бюджет:
  стоимость ядра             8,4 ч
  программа отводит         15,7 ч
  средняя цена слова          92 с
```

### 3.1. Гипотеза из CURRICULUM.md §6.3 подтвердилась

Расчёт бюджета опирался на допущение «40% лексики прозрачны для
русскоязычного». Измерение на реальном ядре: **45%**. Допущение было
скорее консервативным.

### 3.2. Но вместимость всё равно оказалась ниже

Первая версия генератора раскладывала **1092 ввода**. Измерение показало,
что это не помещается:

```
ядро 327 слов (дорогое, с продукцией)       8,4 ч
остаток бюджета                              7,3 ч
при 56 с/слово на узнавание → ещё            469 слов
                                       ────────────
РЕАЛЬНАЯ ВМЕСТИМОСТЬ                        ~800 слов
```

Генератор исправлен: `newWordsPerDay` снижен с 8/10/8/4 до **6/7/6/3**,
итого **804 ввода**. Это не подгонка под красивое число — параметр выведен
из измеренной стоимости.

### 3.3. Итоговая честная картина

| | |
|---|---|
| Вводов за 182 дня | **~800** |
| Из них до воспроизведения | ~330 (ядро) |
| Остальные — до узнавания | ~470 |
| Независимая оценка объёма для B1 | 2500–3000 |
| Покрытие | **примерно треть** |

Чего это достаточно: грамматика, служебная лексика, ложные друзья,
экзаменационные формулировки, базовая тематика по всем 16 областям.

Чего не хватит: свободного чтения оригинальных текстов и спонтанной речи
на произвольную тему. Это нужно добирать вне 15-минутного ядра.

**На лендинге нельзя писать «2500 слов».** Правда — «около 800 отобранных
единиц плюс вся грамматика экзамена».

## 4. Четыре источника

```
scripts/data/vocab-false-friends.mjs    35   критический приоритет
scripts/data/vocab-function.mjs         59   высокий
scripts/data/vocab-verbs.mjs            60   высокий, видовыми парами
scripts/data/vocab-themes.mjs          174   обычный, по 16 темам Katalogu B
                                       ───
                                       327   после дедупликации
```

### 4.1. Ложные друзья

Самая доходная часть словаря. Формат отличается от остальных: кроме
перевода хранится то, **чем слово кажется**, и то, **как сказать
то, что человек имел в виду**.

```jsonc
{
  "lemma": "sklep",
  "translation": "магазин",
  "transparency": "false-friend",
  "interference": { "confusedWith": "склеп", "actuallyIs": "grobowiec" },
  "priority": "critical"
}
```

Это даёт отдельный тип упражнения — контрастный: `sklep` ≠ склеп, склеп =
`grobowiec`. Обычная карточка здесь не работает, потому что ошибка не в
незнании, а в ложном знании.

### 4.2. Служебные слова

Почти все непрозрачны (`ale`, `żeby`, `bardzo`, `trzeba`), хотя короткие.
При этом без них не строится ни одно предложение. Вводятся рано и
привязаны к грамматическим правилам: `żeby` приходит вместе с
`pl.gram.s-subordinate-ze`.

### 4.3. Глаголы — видовыми парами

Одна словарная единица = пара `ndk/dk`, а не два слова. Вид как **понятие**
русскоязычному объяснять не нужно, но конкретные пары часто не совпадают:
`brać/wziąć`, `widzieć/zobaczyć`, `mówić/powiedzieć`.

Отдельно хранится **управление** — падеж дополнения:

```jsonc
{ "lemma": "szukać", "government": "gen", "grammarRuleIds": ["pl.gram.v-government"] }
```

Это прямой материал для дриллов по правилу `v-government` (риск
интерференции 5): `szukam pracy`, а не *`szukam pracę`.

### 4.4. Тематическое ядро

174 единицы по 16 областям Katalogu B. Отбор — частотность × необходимость
для экзаменационных заданий: для описания фотографии нужны внешность и
расположение в пространстве, для `sprawozdania` — транспорт и места.

## 5. Схема записи

```ts
interface Lexeme {
  id: string                 // 'pl.mieszkanie' — всегда с префиксом языка
  lemma: string              // начальная форма
  pos: 'noun'|'verb'|'adj'|'adv'|'conj'|'prep'|'pron'|'part'|'pred'|'phrase'
  translation: string        // на sourceLanguage
  transparency: Transparency
  themeId: string | null     // область Katalogu B
  priority: 'critical'|'high'|'normal'

  aspectPair?: { imperfective: string; perfective: string }
  government?: string        // 'gen' | 'dat' | 'na+acc' …
  interference?: { confusedWith: string; actuallyIs: string }
  grammarRuleIds?: string[]  // связь с правилами
}
```

⚠️ Поля `translation` в единственном числе достаточно, пока пакет один —
`pl-b1-ru`. Для второго языка перевода оно станет
`translations: { ru: …, uk: … }`, как описано в `ARCHITECTURE.md` §4.1.
Менять схему сейчас — преждевременно.

### Чего в схеме намеренно нет

| Поле | Почему нет |
|---|---|
| Словоформы, парадигмы | Генерируются из **Morfeusz 2** (BSD), хранить незачем |
| Транскрипция | Ударение в польском регулярное; исключения — отдельный короткий список |
| Аудио | Браузерный TTS, см. `AUDIO_AND_PRONUNCIATION.md` |
| Частотный ранг | Добавится при расширении до 800 из Leipzig Corpora (CC BY 4.0) |

## 6. Раскладка по дням

Алгоритм в `build-vocabulary.mjs`:

1. Очередь сортируется по приоритету: `critical` → `high` → `normal`
2. Для каждого дня сначала берутся слова **темы его недели**
3. Недобор закрывается служебными словами и глаголами из общей очереди
4. Результат пишется в `curriculum.json` → `day.lexemeIds`

Так ложные друзья и служебная лексика попадают в первые недели, а
тематическая раскладывается по своим неделям.

Сейчас размещено **327/327**: весь словарь помещается в 804 слота, то есть
остаётся место под ещё ~477 единиц.

### Команды

```bash
node scripts/build-vocabulary.mjs   # пересобрать словарь и раскладку
pnpm content                        # программа + словарь + синхронизация
```

Сборка **каждый раз пересчитывает бюджет** и говорит, помещается словарь
или нет. Это главная защита от того, чтобы программа тихо стала
невыполнимой.
